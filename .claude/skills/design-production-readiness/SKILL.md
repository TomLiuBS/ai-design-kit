# Design Production Readiness Checker

## スキルの役割
Figmaで作成したラフデザインを本デザインにするために対応が必要なことを確認し、対応するべきことを提案するスキル。UIデザイナーが本デザイン作成前に確認すべき実務的なチェックリストを提供します。

## スキルの目的
- ラフデザインから本デザインへの移行時の抜けもれを防ぐ
- 実装に必要な画面パターンやパーツの状態を網羅的に洗い出す
- デザインシステムの一貫性と実装効率を高める
- 本デザイン作成時の手戻りを最小化する

## ui-reviewスキルとの違い
- **ui-review**: WCAG、Material Design、Apple HIGなどの業界標準に基づく視覚品質・構造品質の評価
- **design-production-readiness**: ラフデザインから本デザインへの移行時の実務的な準備状況のチェック

ui-reviewは完成したデザインの品質評価、本スキルは本デザイン作成前の準備チェックという位置づけです。

## 入力
- FigmaのデザインURL（ラフデザインが含まれるファイル）
- または、Figmaデザインのスクリーンショット

## フェーズ1: ラフデザイン完成後のチェック項目

### カテゴリ1: 画面・パーツの状態バリエーション

#### 1.1 画面状態のバリエーション
- [ ] **初期表示状態**: データ未読み込み時の表示
- [ ] **データ読み込み中状態**: ローディングインジケーター、スケルトンスクリーン
- [ ] **データ表示状態（正常）**: 標準的なデータ量での表示
- [ ] **データ表示状態（最小）**: データが1件または少数の場合
- [ ] **データ表示状態（最大）**: データが多数ある場合、スクロール・ページネーション
- [ ] **データなし（空）状態**: 検索結果0件、該当データなしの表示
  - **注**: 検索機能がある画面では必須対応。検索以外の画面では推奨対応
- [ ] **エラー状態**: 通信エラー、タイムアウト、システムエラーの表示
- [ ] **成功状態**: 操作完了時の成功メッセージ・フィードバック

#### 1.2 インタラクション状態
- [ ] **ホバー状態**: ボタン、リンク、カードなどのホバー時の見た目
- [ ] **フォーカス状態**: キーボード操作時のフォーカス表示
- [ ] **押下状態（Active）**: ボタンやリンクをクリック/タップした瞬間の状態
- [ ] **選択状態（Selected）**: リストアイテム、タブ、チェックボックスなどの選択時
- [ ] **無効状態（Disabled）**: 操作不可時のボタンやフォームフィールド
- [ ] **ドラッグ中状態**: ドラッグ&ドロップ操作時の表示

#### 1.3 フォーム・入力要素の状態
- [ ] **未入力状態**: プレースホルダー表示
- [ ] **入力中状態**: フォーカス中の見た目
- [ ] **入力完了状態**: 有効な値が入力された状態
- [ ] **バリデーションエラー状態**: 入力値が無効な場合のエラー表示
- [ ] **必須項目の表示**: 必須マーク、ラベルの見た目
- [ ] **ヘルプテキスト**: 入力のヒントやフォーマット例の表示

#### 1.4 モーダル・オーバーレイの状態
- [ ] **モーダル表示状態**: ダイアログ、ポップアップの表示
- [ ] **モーダル背景**: 背景のオーバーレイ、ブラー効果
- [ ] **モーダルクローズ**: 閉じるボタン、背景クリックでの閉じ方

#### 1.5 通知・フィードバックの状態
- [ ] **成功通知**: トースト、スナックバー（成功）
- [ ] **エラー通知**: トースト、スナックバー（エラー）
- [ ] **警告通知**: トースト、スナックバー（警告）
- [ ] **情報通知**: トースト、スナックバー（情報）

### カテゴリ2: 画面サイズ対応

#### 2.1 最小サイズ対応
- [ ] **最小幅対応**: `<DESIGN.md で決めた最小幅>`でレイアウトが崩れないか
- [ ] **最小高さ対応**: `<DESIGN.md で決めた最小高さ>`で主要コンテンツが見切れないか
- [ ] **スクロール対応**: 最小サイズ時のスクロール動作の設計

#### 2.2 レスポンシブ対応（必要に応じて）
- [ ] **デスクトップ**: 1366px以上の標準的なデスクトップサイズ
- [ ] **タブレット横**: 1024px程度
- [ ] **タブレット縦**: 768px程度
- [ ] **スマートフォン**: 375px〜428px程度

#### 2.3 可変要素の設計
- [ ] **可変幅要素**: ブラウザ幅に応じて伸縮する要素の最小・最大サイズ
- [ ] **固定幅要素**: 固定サイズの要素の適切な配置
- [ ] **折り返し処理**: テキストや要素の折り返し時の見た目

#### 2.4 テキスト表示の考慮（重要）
- [ ] **テキスト省略ルール**: 長いテキストを省略する場合のルール（1行省略、2行省略、最大文字数など）
- [ ] **テキスト折り返しルール**: テキストを折り返す場合の行数制限
- [ ] **エリアが狭い場合の対応**: 画面幅が狭い場合のテキスト表示方法
- [ ] **省略時のツールチップ**: 省略されたテキストの全文表示方法

### カテゴリ3: レイヤー命名規則

#### 3.1 命名規則の遵守
- [ ] **ローワーキャメルケース**: 例）`buttonPrimary`, `cardHeader`, `listItem`
- [ ] **アンダースコア不使用**: 「_」は使わない
- [ ] **要素の種類が明確**: ボタン、カード、リスト、アイコンなど要素タイプが分かる
- [ ] **役割の明確な表現**: 各レイヤー・要素の役割を名前から理解できる
- [ ] **階層構造が明確**: 親子関係が名前から理解できる

**グループ化規則**:
- [ ] **container**: 数パーツの入れ物（例: `searchContainer`）
- [ ] **content**: コンテナに入っている内容（例: `searchContent`）
- [ ] **～Area**: セクション・範囲を示す（例: `headerArea`）
- [ ] **control**: 操作・入力する要素の集まり（例: `searchControl`）

**フレーム命名規則**:
- [ ] **フレーム名の形式**: 「画面ID_画面名_画面状態」の形式で統一
  - 例: `D_T_02_01_01_requestList_normalSearch`

#### 3.2 禁止事項の回避
- [ ] **連番のみの命名を避ける**: `Frame 1`, `Group 2`などの自動命名を修正
- [ ] **日本語のみの命名を避ける**: 英語命名を推奨（例: ❌ `検索ボタン` → ✅ `searchButton`）
- [ ] **アンダースコアを使用しない**: ローワーキャメルケースで区切る

### カテゴリ4: アセット・リソースの準備

#### 4.1 イラスト・アイコン
- [ ] **仮イラストの検出**: ラフデザインに含まれる仮イラストの特定（本制作が必須対応）
- [ ] **カスタムイラスト**: 新規作成が必要なイラストのリストアップ
- [ ] **カスタムアイコン**: 新規作成が必要なアイコンのリストアップ
- [ ] **既存アセットの確認**: デザインシステムに既存のアセットがあるか確認

#### 4.2 カラー・スタイル
- [ ] **カラーパレット定義**: 使用する全カラーが定義されているか
- [ ] **カラー変数名**: 色の用途が分かる変数名（例：`primaryBlue`, `errorRed`）

### カテゴリ5: 実装考慮事項

#### 5.1 アニメーション・トランジション
**推奨アニメーション提案**:
- [ ] **ページ読み込み時**: フェードイン、スライドイン（200〜300ms）
  - 推奨: リストアイテムを上から順にフェードイン（50msずつ遅延）
- [ ] **検索結果表示**: フェードイン、スケールアニメーション
  - 推奨: 検索結果エリア全体をフェードイン（300ms）
- [ ] **ローディング**: スピナー回転、スケルトンシマー効果
  - 推奨: スケルトンスクリーンに左から右へのシマーアニメーション（1500ms、無限ループ）

#### 5.2 データ構造との整合性
- [ ] **API連携要素**: APIから取得するデータで表示する要素の確認
- [ ] **動的コンテンツ**: 文字数や項目数が可変な要素の最大・最小パターン
- [ ] **null/undefined対応**: データが存在しない場合の表示

## フェーズ2: 本デザイン完成後のチェック項目

### カテゴリ7: 本デザインの完成度確認

#### 7.1 全画面・状態パターンの作成確認
- [ ] **計画された全画面が作成済み**: フェーズ1で洗い出した全画面パターンが作成されているか
- [ ] **全状態バリエーションが作成済み**: ホバー、フォーカス、エラーなど全状態が網羅されているか
- [ ] **画面遷移の整合性**: 各画面間のリンクや遷移が矛盾なく設計されているか

#### 7.3 デザインシステムとの整合性
- [ ] **カラーパレットの準拠**: 全ての色がデザインシステムのカラーパレットから使用されているか
- [ ] **タイポグラフィの準拠**: フォントサイズ、行間、太さが規定に従っているか
- [ ] **余白システムの準拠**: 8pxグリッドシステムなど、定義された余白ルールに従っているか

#### 7.6 アクセシビリティ要件の確認
- [ ] **タッチターゲットサイズ**: ボタンやリンクが最小44x44px以上か
- [ ] **コントラスト比**: テキストと背景のコントラスト比がWCAG AA基準（4.5:1以上）を満たすか

## 出力フォーマット

チェック結果は以下の形式で出力します:

```markdown
# 本デザイン作成準備チェック結果

## 対象デザイン
- ファイル名: [Figmaファイル名]
- 対象画面: [画面名]
- チェック日: [日付]

## サマリー
- ✅ 対応済み: X項目
- ⚠️ 要対応（必須）: Y項目  
- ℹ️ 推奨対応: Z項目
- ➖ 確認不要: W項目

## 優先度別 TODO リスト

### 🔴 高優先度（本デザイン作成前に必須）
1. ✏️ [対応内容]

### 🟡 中優先度（本デザイン作成時に対応推奨）
1. ✏️ [対応内容]

### 🟢 低優先度（時間があれば対応）
1. 📱 [対応内容]
```

## 使用方法

```
デザイン作成準備のチェックをして
https://www.figma.com/design/<fileKey>/...
```

フェーズを指定する場合:
```
【フェーズ1】デザイン作成準備のチェックをして
https://www.figma.com/design/<fileKey>/...
```

## 推奨実行順序

1. ラフデザイン完成 → **design-production-readiness（フェーズ1）**
2. 本デザイン作成
3. 本デザイン完成 → **design-production-readiness（フェーズ2）**
4. 最終調整 → **ui-review**
5. 実装開始
