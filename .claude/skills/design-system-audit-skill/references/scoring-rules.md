# 点と重大度の決め方（Core）

**誰が実施しても同じ点・同じ重大度・同じ修正リストになるよう、AIがその場で判断する箇所をこの表に置き換える。** 評価（SKILL.md「3. 評価」）と修正リスト（出力仕様）は、このファイルに従う。表にない判断が要るときは、点を推測せず「要確認」に回し、このファイルへの追記を提案する。

- 正しい形の定義は `guidelines/rules/` にある。このファイルは「測った値・確かめた事実を、何点・どの重大度にするか」だけを決める。
- ルール未定の論点（例：赤の表し方、Componentの中のInstanceの名前、フォーカスの表し方）は、決まるまで点に入れない。各項目の「ルール未定の扱い」に従う。

## 1. 換算表（暫定値）

測った値は、次の表で点にする。**値が同じなら、誰が実施しても同じ点になる。** 閾値は暫定で、複数回のDSレビューの結果を見て人が見直す（見直したら、このファイルの更新履歴に書く）。

### 1-1. 率の表（違反率）

| 違反率 | 点 |
|---|---|
| 0%（違反0件） | 2 |
| 0%より大きく10%未満 | 1 |
| 10%以上 | 0 |

- 適用率で測る項目（D1・E6 など）は、`違反率 = 100% − 適用率` にして同じ表を使う。
- 分母が0のときは N/A とし、理由を書く。

### 1-2. 件数の表（欠け・汎用語の数）

| 件数 | 点 |
|---|---|
| 0件 | 2 |
| 1件 | 1 |
| 2件以上 | 0 |

## 2. 項目ごとの点の決め方（Core 26項目。うちHの3項目は得点外）

「測定」は design-system-measure のスクリプトの値を使う。「確認」は、書かれた問いに順に答え、答えと証拠を付録Cに書く。**問いの答えが「確認できない」ときは、その項目を未検証にする（0点にしない）。**

| A1 | 確認 | ①対象がComponent Set／Componentとして作られているか（いいえ→0）。②Componentの中で、DSに既にある部品（アイコン等）をInstanceにせず、FRAME・GROUP・ベクターで直接描いた箇所があるか（ある→1）。③どちらもなければ2 |
| A3 | 確認 | ①同じファイルの公開Component Set名に、対象と同じ役割の語を含むもの（類似資産）があるか（ない→2）。②類似資産のうち正本が `🚫`（V-08）または Description で分かるか（分かる→2、分からない→1）。③同名で構造が違うComponent Setがある（V-06 名前の一意性）→0 |
| A4 | 測定（率の表） | Script E の `a4.noProperty / a4.eval`（先頭のバリアントの直下にある TEXT と INSTANCE のうち、Component Property（Text／Instance swap／Boolean）が付いていないものの割合） |
| A5 | 測定（率の表）＋上限 | Script D の Property名の違反率（`props.flagged / props.eval`）で点を出す。ただし、既定のバリアント（Setの先頭の子）の値に V-05-2 で使わない値（`default` 等）がある、または Instance swap の既定が素材名（`sample` 等）のときは、**1点を上限**にする |

## 3. 重大度の表

修正リスト・要確認の重大度は、次の表で決める。**「AIが別の物として扱う違い」は🟠、「表記の揺れ」は🟡。** 表にない種類は🟡とし、要確認に「重大度の表にない種類」として挙げ、この表への追記を提案する。

| 重大度 | 事実の種類 | 例 |
|---|---|---|
| 🔴 | 正本が分からず、類似資産の間で同じ値が違う見た目を持つ（主要な画面に影響する） | 同じ用途の部品が2つあり、`type=primary` の色が違う |
| 🟠 | `state` の値が V-05-2 の一覧にない（`default` `active` `on/off` を含む） | `state=default`→`normal` |
| 🟠 | 軸名が V-04 に違反する | `status`→`state` |
| 🟠 | 1つの軸に別の種類の差分が混ざっている（CA-02・CA-07） | `state` に赤の差分が入っている |
| 🟠 | Description が空、または用途がない（F1）／類似資産との選び分けがない（F2） | |
| 🟠 | 類似資産の正本が分からない（A3） | |
| 🟠 | Figmaと `guidelines/` の対応表で、対応先が食い違う（I2） | `type=gray` の対応先が違う |
| 🟡 | `size` の値が V-01 の一覧にない | `extralarge`→`xlarge` |
| 🟡 | 値・名前のケース・記号・空白の揺れ（V-05-4・V-06・V-07） | `white_no border`→`whiteNoBorder` |
| 🟡 | レイヤー名の形式違反（layer-naming-rules） | 素材名のまま |
| 🟡 | 既定値が素材名・サンプル（A5） | `sample1` |
| 🟡 | 汎用語の名前（C9） | |
| 🟡 | Auto Layout 未適用（D1）／状態の欠け（B3）／組合せの欠け（B5） | |
| 🟡 | CSS・対応表に状態やサイズが足りない（I2のうち、対応先の食い違い以外） | hover がない |

- ルール未定の論点の重大度は、SKILL.md の現行の決め方（関連する修正より1段階上げる）のままとする（ルール未定の扱いは保留中）。

## 4. 修正リストの行の作り方

- **1行 ＝ 1つのルールID × 1つの対象（軸の値・名前・レイヤー名の種類）。** 同じルールIDで同じ直し方のものは1行にまとめ、件数を書く。
- **永続ID** を付ける：`<対象>/<ルールID>/<部位>-<現在の値>`（例：`iconButton/V-05-2/state-default`、`iconButton/V-01/size-extralarge`）。No. は表示用の連番で、再レビューの対応は永続IDで取る。
- **並び順**：出力仕様の段階（①〜⑥）の順 → 同じ段階の中はルールIDの昇順 → 同じルールIDの中は現在の値のアルファベット順。
- **「提案：」の値**：ルールに変換の対応（variant-naming-rules 第2節「機械的変換の規則」、V-05-1・V-05-2 の対応）があるときは、その値を必ず使う。対応がないもの（例：`active` が `pressed` か `selected` か）は、両方の候補を並べて「要決定」にする。
- 修正リストに載せるのは、**①ルールIDで違反が確かめられたもの**と、**②このファイルで0点・1点になった項目の直し方**だけ。ルールにない構造の工夫（新しい軸の追加など）は、付録「H. 追加提案（得点外）」に分ける。
