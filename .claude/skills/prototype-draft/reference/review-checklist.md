# review-checklist.md — レビュー判定基準

[SKILL.md](../SKILL.md) STEP5で使う固定チェックリスト。主観的な良し悪しではなく、この項目の合否だけで判定する。

## 1. コンポーネント・トークン

- [ ] 使用しているクラス名はすべて`guidelines/kit/components.css`（サービス固有なら`guidelines/<service>/components.css`）に実在するか
- [ ] 色・余白・角丸・フォントサイズはすべてCSS変数（`var(--xxx)`）で書かれているか（生値の直書きがないか）
- [ ] guidelinesに存在しないコンポーネント・トークンを、感覚で自作・代替していないか

## 2. 参照優先順位

- [ ] ビジュアルがguidelines（DS）と一致しているか
- [ ] 実装コード（`external/`）を参照した場合、それはDS未定義のビジュアル・挙動ロジックの補完に限定されているか
- [ ] DSと実装コードの見た目が食い違う箇所で、DSを優先しているか

## 3. 状態網羅

- [ ] [state-checklist.md](state-checklist.md)・[screen-type-presets.md](screen-type-presets.md)に基づき、該当する状態がすべて実装されているか
- [ ] 該当しないと判断した状態が、省略でなく明記されているか

## 4. 出力ルール

- [ ] 保存先・ファイル名がPROTOTYPE.md 8章のルールに沿っているか
- [ ] 既存ファイルを無断で上書きしていないか（明示指示がない限り`-v2`等の版を付けているか）
- [ ] 不採用案・一時ファイルが残っていないか

## 5. Figma照合・部品・アイコン

- [ ] 画面に出る部品とアイコンを、`component-map.md` / アイコン一覧で引いたか（「未定義」の部品を自作していないか）
- [ ] DS部品（スナックバー・選択メニュー・ラジオ/チェックボックス・トグル・ヘッダーなど）は、DSのクラスをそのまま使っているか
- [ ] アイコンは Material Symbols Outlined のリガチャ名か、チームで決めたカスタムアイコンの置き場の画像（`<img>`）か。`material-icons`（旧フォント）や `mask-image` を使っていないか
- [ ] 状態違いのFigmaフレーム（初期表示・選択時・開いた状態など）を確認し、最新のFigmaを取得したか
- [ ] 状態が変わる部品は、元のComponentSetの状態（`style` 軸など）を一覧にし、`components.css` の状態と突き合わせたか。Figmaにあってクラスにない状態・値の違いを、作る前に仕様表へ載せたか。`prototype.css` の上書きで済ませていないか（[PROTOTYPE.md](../../../PROTOTYPE.md) 4-2）
- [ ] 主要要素の位置・幅・高さをFigmaと照合したか（差2px以上は修正済みか）
- [ ] 余白は適切か。固定メニュー・サイドメニュー・カード・ダイアログなど**囲みのある領域ごと**に、内側の上下左右の余白を実測し、Figma（なければガイドラインの余白トークン）と一致しているか。中身が囲みの高さぎりぎり（上下の余白が片側8px未満）になっていないか。部品どうしの間隔（gap）もFigmaと照合したか
- [ ] 罫線・区切り線は、**上側と下側の余白**をそれぞれ実測し、Figma（指定がなければガイドライン）の値どおりか。上下で値が違っていないか（Figmaで上下が同じなら同じ値になっているか）。余白の指定は、指定されたFigmaのノードか、ガイドラインのどちらに合わせたかを確認できる状態にする
- [ ] 部品のサイズ（size バリアント）は、Figmaの該当画面で使われているものと一致しているか（例: ボタンの small/medium/large）。サイズ名の推測で選んでいないか
- [ ] `file://`（ファイルを直接開く）でも崩れず表示されるか
- [ ] ボタン・メニューの動きは component-map の標準に従い、画面固有の動きだけをユーザーに確認したか
- [ ] `NOTES.md` に決定事項を残したか（30行以内。小さな修正では不要）

## 判定

- 上記すべてに合格 → **合格**。完了報告へ進む
- 1つ以上不合格 → 該当箇所を指摘し、[SKILL.md](../SKILL.md) STEP4に戻って修正（**差し戻し上限2回**）
- 2回差し戻しても解消しない項目がある場合 → 残件リストを添えて人間に判断を委ねる
