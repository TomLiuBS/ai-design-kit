# キャプチャ結果のレイヤー名を、ルールに沿って付ける手順

ルールの正本は [layer-naming-rules.md](../../../../guidelines/rules/layer-naming-rules.md)。ここにはルールを書き写さず、**キャプチャ結果にどう当てはめるか**だけを書く。

## なぜ必要か

キャプチャしたレイヤー名は、HTMLのタグやclass由来の名前になる（`Container` `Text` `Button - …` `Article` `Heading 1` `h2d-svg-use-0` など）。これらは `R-02`（日本語）、`R-03`（記号・スペース）、`R-05`（デフォルト名）、`R-09`（数字）の違反になる。置換のあと、**画面全体の名前を付け直す**。

## 対象

| 対象 | 扱い |
|---|---|
| 最上位のフレーム | F-01 の形式にする（下記） |
| 置換していないフレーム（入れ物・テキストの枠・画像の枠） | R-01〜R-10 に沿って付け直す |
| 置換したインスタンス自体 | ルール上は対象外だが、キャプチャ由来の長い日本語名（例：`Button - 出張申請 営業部のプレビュー`）が残るので、役割名にする |
| インスタンスの内部 | リネームしない（対象外） |
| TEXTノード | 表示テキストと同名なら対象外。リネームしない |
| `Vector` などの図形系の既定名 | 対象外。そのままでよい |

## 最上位のフレーム（F-01）

`画面ID-画面名-画面状態-画面サイズ`

- 画面IDは空欄を許容する。空欄なら、ID部分と直後の `-` ごと省略する（推定して入れない）
- 画面名は必須（日本語可、`-` は使わない）
- 画面状態は必須（自由記述）。取り込んだ状態を書く（例：`初期状態`）
- 画面サイズは `w` ＋ 幅の数字（例：`w1024`）
- 例：`申請一覧-初期状態-w1024`

## キャプチャ名 → 役割名の対応

HTMLの構造から決まる名前は、次のように付ける。ここにない箱は、**中身を見て役割名にする**。

| キャプチャの名前 | 役割名 | 備考 |
|---|---|---|
| `Body` | `content` | 親の主たる中身 |
| `Header` | `header` | |
| `Header:margin` などの `:margin` 付き | 役割名＋`Area`（例：`headerArea` `menuButtonArea`） | 余白用の包み |
| `Heading 1` | `title` | |
| `Sidebar` | `sidebar` | |
| `Main Content` | `main` | |
| `Section - …` | 役割名＋`Area`（例：`requestListArea`） | `section` は禁止語（R-07） |
| `Article` | `〜Card`（例：`requestCard`） | |
| `Label`（ラジオの行など） | `radioItem` など、同じ役割の繰り返しは同名にする（R-04） | |
| `Image - …` | `thumbnail` など用途名 | 中の `h2d-svg-use-0` は `artwork` など |
| `Button - …`（フレームのまま残るもの） | `〜Button`（例：`drawerButton`） | |
| `Text` / `Text:margin`（枠のフレーム） | `name` `label` `hint` など役割名 | TEXTノード自体は触らない |
| 高さや幅が0〜2pxの枠 | `topSpacer` `bottomSpacer` `divider` など | |
| `Container`（同じ親に1つだけ） | `container` のままでよい | 同じ親に複数あるなら、役割名＋`Area` にする |

## 気をつけるルール

- **禁止語：** `group` `section` `wrapper` `box` `block` `row` `col` を単語として含めない（R-07）。**`requestBox` も違反になる。** 「〇〇ボックス」と呼ばれる部品は `requestItem` `requestList` などにする
- **数字：** 名前に数字を入れない（R-09）。`h2d-svg-use-0` → `artwork`、`stamp1` → 役割名
- **略語：** `btn` `img` `bg` を使わない。フルスペルにする
- **語順：** 修飾語が先（`leftIcon`、`sortSelect`）
- **同じ親の直下：** 役割が違う箱に同じ名前を付けない。`container`（単独）は1つだけ
- **同じ役割の繰り返し：** 同名でよい（`requestCard`、`radioItem`）

## 付け直しのやり方（`use_figma`）

1. 置換のあとに、画面のフレームを一度ダンプし、非インスタンスのフレームの `id / 名前 / 大きさ / 中のテキスト` を一覧にする
2. 上の対応表と、中身から決めた役割名を `id → 名前` の対応にする。繰り返し要素（カードなど）は、構造（子の順番）から付ける
3. `node.name = …` で付け直す

## 検証（必須）

付け直した直後に、次を満たさない名前が0件であることを `use_figma` で確かめる。

- インスタンスの内部、TEXTノード、図形系の既定名（`Vector` など）は除く
- 正規表現 `^[a-z][a-zA-Z0-9]*$` に一致する（最上位のフレームを除く）
- 数字を含まない（R-09）
- 禁止語（R-07）を単語として含まない

0件でなければ、残りを付け直す。判断に迷う名前は、ルールどおり「要確認」としてユーザーに出す。
