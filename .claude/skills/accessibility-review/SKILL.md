# アクセシビリティレビュー

---

## ⚠️ 発動条件（必須）

以下の2点がそろった場合のみレビューを開始する。不足している場合は質問して確認する。

| # | 必須インプット | 説明 | 未指定の場合 |
|---|--------------|------|------------|
| 1 | **アクセシビリティチェック依頼** | 「アクセシビリティチェックをして」「アクセシビリティレビューをして」等 | スキルを発動しない |
| 2 | **対象サービス名** | 基準テーブルに列があるサービス名 | 必ず質問して確認する |

> **サービス名の判定基準:**
> - **基準テーブルに記入済みの列があるサービス** → その列の必達/推奨/適用外を使用
> - **列がない、または空欄が残っているサービス** → 「未定義」と明記し、WCAG AA を基準として評価（空欄の行だけ未定義として扱う場合も、その旨をレポートに書く）

---

## 簡単な使い方

**モードA（静的レビュー）:**
```
<サービス名>のアクセシビリティチェックをして
https://www.figma.com/design/<fileKey>/...
```
または:
```
<サービス名>のアクセシビリティレビューをして
[スクリーンショット]
```

**モードB（静的+動的レビュー）:**
```
<サービス名>のアクセシビリティチェックをして
https://www.figma.com/design/<fileKey>/...
<repo>/docs/<画面要件書>.md
```

---

## ⚠️ 実行ルール（必須）

1. **発動条件（サービス名 + 依頼）を確認してから開始する**
2. **全WCAG基準（A/AA/AAA: 86項目）を個別評価する**
3. **各項目に判定（✅/❌/⚠️/N/A/要実装確認）とスコア（1〜5）を付与する**
4. **スコア根拠を具体的に記述する**（「コントラスト不足」× → 「#767676と白背景のコントラスト比3.9:1、基準4.5:1未達」○）
5. **適用外の項目は自動的にN/Aとし、理由を一言添える**
6. **動的項目（モードBのみ）で要件書に記載のない項目は「要実装確認」とし、末尾に一覧出力**
7. **詳細評価（セクション6）はスコア3.5点以下かつN/A・要実装確認以外の項目のみ出力**
8. **レポートはドキュメントとして作成する**

> **パフォーマンスについて:** AAAを含む全86項目を評価するため、レビューは詳細になります。適用外の項目はN/A処理で迅速に対応します。基準テーブルで適用外とした項目（手話・キーボード例外なし等）が多いサービスでは、実質的な評価項目はこれよりも少なくなります。

---

## 概要

| | モードA（静的） | モードB（完全） |
|---|---|---|
| **インプット** | Figma URL または スクリーンショット | Figma URL + 画面要件書 |
| **評価基準** | WCAG A/AA/AAA 86項目 + ui-review 28セクション | 同左 |
| **評価範囲** | 視覚的・静的に確認できる項目 | 静的 + 動的・インタラクション |
| **未確認項目** | 動的項目はすべてN/A | 要件書で確認できない項目を「要実装確認」として末尾に列挙 |

---

## Step 1: 必須インプットの確認

| 確認事項 | 内容 |
|---------|------|
| **対象サービス** | 基準テーブルに列があるサービス / その他（サービス名 + 「未定義」） |
| **モード** | Figma URL + 要件書あり → モードB / それ以外 → モードA |
| **追加基準** | サービス固有の追加要件（色覚障害対応強化・読み上げ指定など）があれば記載 |

---

## Step 2: モード判定

| 条件 | モード |
|------|------|
| Figma URL または スクリーンショットのみ | **モードA**（静的レビュー） |
| Figma URL + 画面要件書 | **モードB**（完全レビュー） |

---

## 評価方式

**5段階スコア + N/A + 要実装確認:**
- **5点**: チェック項目100%充足
- **4点**: 80%以上充足
- **3点**: 60%以上充足
- **2点**: 40%以上充足
- **1点**: 40%未満
- **N/A**: 評価不能（適用外・該当なし・画像限界）
- **要実装確認🔍**: 実装後テストが必要（モードBのみ）

**判定記号:**
- ✅ 基準を満たしている
- ❌ 基準を満たしていない
- ⚠️ 一部不満足
- 🔍 要実装確認

- `<サービス名>` を実際のサービス名に置き換える。サービスが1つなら列は1つでよい。増えたら列を足す

# Part 1: 視覚品質（画像で評価可能・18セクション）

> ui-reviewと同一の評価項目です。

## 1. 空間デザイン

### 1.1 整列（5項目）
- [ ] すべての主要要素の左端または右端が揃っている
- [ ] テキストと要素が左揃え、右揃え、中央揃えのいずれか1つに統一されている
- [ ] 異なる整列方法が意図なく混在していない
- [ ] 要素の端が視覚的に同一の垂直線または水平線上に配置されている
- [ ] 同種要素の端が仮想の垂直線または水平線から2要素以上外れていない

**判定:** [ 1 / 2 / 3 / 4 / 5 / N/A ]

### 1.2 余白の一貫性（5項目）
- [ ] 同じ種類の要素間の余白が3種類以上に見えない
- [ ] セクション内の余白がセクション間余白の半分以下に見える（近接の原則）
- [ ] 同種要素間の余白が2種類を超えない
- [ ] セクション間の余白がセクション内の余白より大きい（2倍以上）
- [ ] 要素同士が接触・重なっている箇所がない

**判定:** [ 1 / 2 / 3 / 4 / 5 / N/A ]

### 1.3 レスポンシブ対応（4項目）
- [ ] モバイル（320px〜767px）のデザインが存在する
- [ ] タブレット（768px〜1023px）またはデスクトップ（1024px〜）のデザインが存在する
- [ ] 縦向きと横向きの両方のデザインが存在する
- [ ] 各画面サイズでコンテンツが画面内に収まっている

**判定:** [ 1 / 2 / 3 / 4 / 5 / N/A ]

## 3. 一貫性

### 3.1 デザインパターンの統一（5項目）

## 5. 操作要素

### 5.1 ボタンの配置とサイズ（5項目）
- [ ] 20px×20px未満に見えるボタンが存在しない（正確なサイズ計測はPart 2 7.4で実施）
- [ ] Primary Actionボタン（保存、送信等）が他のボタンより大きい、または目立つ色である

# レポート形式

### 評価スコア基準
- **4.5〜5.0点**: 優秀 - 基準に完全準拠
- **4.0〜4.4点**: 良好 - 十分な品質
- **3.0〜3.9点**: 標準 - 改善の余地あり
- **2.0〜2.9点**: 要改善 - 優先的に対応が必要
- **1.0〜1.9点**: 不十分 - 即座に対応が必要

### レポート構造
```
1. 概要（評価対象・対象サービス・基準・モード・評価日・総合スコア）
2. 必達項目 適合状況（対象サービスの必達基準への適合サマリー）
   ├ 適合: [n]項目
   ├ 非適合: [n]項目  ← 🔴 最優先で対応
   └ 確認不足（要実装確認）: [n]項目
3. 推奨項目 評価サマリー（改善候補の一覧・優先度付き）
4. 視覚品質評価サマリー（ui-review準拠・Part 1〜2）
5. 改善推奨事項
   ├ 🔴 必達・非適合（必ず対応）
   ├ 🟡 推奨・優先度高（できれば対応）
   └ 🟢 推奨・優先度中（余裕があれば対応）
6. 総括（強み・改善領域・次のステップ）
7. 詳細評価（スコア3.5点以下かつN/A・要実装確認以外の項目のみ）
8. 要実装確認項目リスト（モードBのみ）
9. 適用外項目リスト（対象サービスで適用外となった基準の一覧）
```

### 要実装確認項目リスト（モードBのみ）

```markdown
## 要実装確認項目

以下の項目はデザインまたは要件書では確認できませんでした。
実装後にテスト・レビューが必要です。

| No. | WCAG番号 | 項目名 | 対象サービス判定 | 確認できなかった理由 |
|-----|---------|------|:------------:|------------------|
| 1 | 2.4.3 | フォーカス順序 | 必達 | 要件書に記載なし |
| ... | ... | ... | ... | ... |
```

### 必達/推奨/適用外の表示形式

各項目の冒頭に以下を表示する:
- 必達項目: `🔴 [必達]`
- 推奨項目: `🟡 [推奨]`
- 適用外: `⬜ [適用外]`
- サービス基準未定義: `⚪ [WCAG AA基準]`

## 重要な注意事項

1. **具体的な数値を記載する**（コントラスト比・サイズ・間隔値など測定値を必ず記録）
2. **改善提案は実行可能に**（「コントラストを改善」× → 「テキスト色を#595959に変更し、コントラスト比を4.6:1に向上」○）
3. **必達・非適合は冒頭に集約する**（優先度が伝わる構成にする）
4. **適用外項目は理由を一言添えてN/Aとする**（例: 「キーボード操作はタッチ主操作のため適用外」）
5. **利用者特性に関わる項目は特に丁寧に評価する**（基準テーブルの「対象特性」に書いた利用者に影響する項目。例: タッチターゲット・色覚対応・閃光）
