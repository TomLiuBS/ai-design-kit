# Figma レイヤー命名ルール

レイヤー名の形式を定めるルール。**AIがレイヤーを一意に特定し、操作できること**を目的とする。

この文書が命名ルールの正本である。スキルは本文書を参照し、スキル側で別基準を定義しない。

配置: `guidelines/rules/layer-naming-rules.md`

参照元: `figma-review-layers` スキル、`design-system-audit`（C4の判定）

**このルールは複数の生成AI（Claude Code / Codex / Figma Agent）が参照する。** ランタイム側で別基準を定義しない。成果物ではないため `generated/` 配下には置かない。

関連ルール: [variant-naming-rules.md](variant-naming-rules.md)（Component Set 名・Variant・Property の命名）、[description-format.md](description-format.md)（Description の記載形式）

---

## 1. 適用範囲

### 対象

| 対象 | 扱い |
|---|---|
| 画面フレーム配下の一般レイヤー | R-01〜R-10 で評価 |
| DS公開Componentの内部レイヤー | R-01〜R-10 で評価 |
| Component Property の対象レイヤー | R-01〜R-10 ＋ Property名との対応を確認 |
| 非表示レイヤー | **評価対象に含める**（状態の出し分けに使われ実装対象になるため） |

### 対象外

| 対象外 | 理由 |
|---|---|
| Component / Component Set の**名前そのもの** | Figmaのコンポーネント名として別のルールに従う |
| Instance とその内部 | 名前はメインコンポーネント由来。内部はAPI上リネーム不可 |
| **ガイドライン文書のページ** | 文書レイアウト用のフレームであり、実装対象ではない |
| TEXTノードが表示テキストと同名のもの | Figmaの既定の自動命名。リネームすると本文変更が名前に反映されなくなる |
| 図形系のFigma既定名（`Rectangle` `Line` `Arrow` `Ellipse` `Polygon` `Star` `Vector` `Path` `Union` `Subtract` `Intersect` `Exclude`、数字付き含む。日本語版既定名も同様） | Figmaのデフォルト名のまま使いたいため、例外的に許容する（R-01〜R-09を適用しない）。詳細はR-05の「図形系の許容」を参照 |
| フレーム内のImage（`Image` `Image 12` `画像`） | 図形系と同じ扱い。フレーム外の単独ImageはR-10で違反 |
| 対象トップフレーム | F-01（第6節）で別途評価 |

## 2. 基本形式（R-01〜R-03）

レイヤー名は正規表現 **`^[a-z][a-zA-Z0-9]*$`** にマッチする英語の lowerCamelCase であること。

ただし、次の名前はこの正規表現で判定しない。

1. R-02の許容語1語と完全一致する名前（R-02の例外）
2. 第1節「対象外」の名前（図形系・フレーム内Imageの既定名など）
3. 対象トップフレーム（F-01で判定する）

マッチしない場合、原因に応じて次を報告する。

| ルール | 内容 |
|---|---|
| R-01 | 英数字のみの lowerCamelCase にする（❌ 先頭大文字・全大文字 等） |
| R-02 | 英語（ASCII文字）で表記する（❌ 日本語・全角文字） |
| R-03 | 記号を使わない英数字のみで表記する（❌ スペース・`/`・`_` 等の半角記号） |

**併記ルール**: R-02 または R-03 に該当する場合、R-01 は併記しない（記号・日本語を取り除いた上でケースも直した修正案を1つ出す）。

### R-01 の細則

- 数字は原則含めない（R-09を参照。R-09の例外の表に当てはまる形のみ使用可）
- 頭字語・略語由来の語は全小文字化してつなぐ（✅ `pdfIcon` `qrCode` / ❌ `PDFIcon` `QRCode`）
- **ローマ字は英語とみなさない**（❌ `shinseiIchiran` → ✅ `requestList`）。ローマ字と判断した場合は英訳した修正案を提案する。**ただし、個別に承認した外来語は英語として扱う（承認した語はここに列挙する。例：`<承認した外来語>`）。** 外来語は語ごとにユーザーが判断する（承認前は「要確認」）

### R-01 の語順細則

レイヤー名が「役割語（主辞）＋修飾語」の複合語になる場合、英語として自然な名詞句の語順（**修飾語を先、役割語を後ろ**）にする。

修飾語の例：方向（`left` `right` `top` `bottom`）、サイズ（`large` `small`）、色（`red` `blue`）、種別を表す形容詞・名詞修飾（`dropdown` `table` 等）。役割語（主辞）は第5節「推奨語彙」の語を基本使用する。

| ✅ 良い例 | ❌ 悪い例 |
|---|---|
| `leftIcon` | `iconLeft` |
| `largeCard` | `cardLarge` |
| `redBadge` | `badgeRed` |

- 既存の `closeButton` `dropdownIcon` `tableHeader` はこの語順に合致している（`close` `dropdown` `table` が修飾語、`button` `icon` `header` が役割語）
- どちらが修飾語でどちらが役割語か判断に迷う複合語は「要確認」とする

### R-02 の例外（業務固有語の日本語許容）

R-02（英語表記）には例外がある。**他アプリでも通じる一般的なUI語は英語化必須**だが、**業務ドメイン固有で英訳すると意味が伝わりにくい語**は日本語を許容する。

判断基準：

| 状況 | 扱い |
|---|---|
| 一般的なUI要素語（label / button / icon 等） | 英語化必須。日本語は違反のまま |
| 業務固有・英訳すると意味が狭まる／通じない | 日本語を許容。ただし表記（送り仮名・漢字/かな）は統一する |
| **アプリ名**（例：`<サービス名>`） | **この例外の対象外＝日本語は許容しない。英語（ローマ字表記を含む）に統一する**（[variant-naming-rules.md](variant-naming-rules.md) V-04-2の`app`軸を参照） |
| **アプリ内の機能名**（例：`<機能名>`） | **日本語で表記する**（アプリ名ではないため） |

**1つの名前に日本語と英語を混在させない**。レイヤー名・Component Set名とも、名前は「すべて英語のlowerCamelCase」か「すべて日本語」のどちらかにする（[variant-naming-rules.md](variant-naming-rules.md) V-04-2の「同一軸内で英語・日本語を混在させない」と同じ考え方）。❌ `稟議Check` `statusArea稟議`。日本語にできるのは、**名前全体が下の許容語リストの1語と完全一致する場合**に限る（例：許容語リストに `稟議` `差戻し` を登録した場合の `稟議`）。**許容語は単独で使い、2語以上つなげない**（❌ `稟議差戻し`）。許容語以外の語（`確認` `エリア`等）を含む名前と、許容語をつなげた名前は、全体を英語にする（例：`稟議確認`→`approvalRequestCheck`）。Component Set名も同じ（[variant-naming-rules.md](variant-naming-rules.md) V-06）。

**許容語リスト（確定）** — 運用の中で承認された語を記録する。**このリストは確定ではなく、随時追加・修正する前提で運用する。**

| 語 | 理由 |
|---|---|
| `<業務固有語>` | サービス固有の固有名詞・業務固有語は、ここに許容語として列挙する（例：`<業務固有語>`）。導入先で承認した語から追加する |

**候補（審査待ち）** — レビュー中に見つかった、英訳すると意味が伝わりにくい業務固有語の候補。昇格の可否はユーザーが判断する。

| 候補語 | 想定理由 | 検出元 | 状態 |
|---|---|---|---|
| （まだなし） | | | |

- 候補は `design-system-audit` スキルのレビュー時に提示される（詳細は同スキルの `naming-criteria.md` を参照）
- 承認されたら「許容語リスト（確定）」に移し、第8節の更新履歴に記録する
- 英語で十分通じると後から判明した場合は、リストから外し英語化を提案する

### R-03 は全てNG。優先度は「報告順」を表す

**記号を含む時点で全てNG（R-03違反）。例外はない。** 以下の「報告優先度」は違反かどうかの判定ではなく、複数の記号違反がある場合にどれから報告・修正するかの順番を表す。

| 記号 | 実例 | 判定 | 報告優先度 | 理由 |
|---|---|---|---|---|
| スペース | `titleArea row g-16 p-16` | NG | 1（即個別報告） | 検索・API操作でレイヤーを特定できない |
| `/` | `icon / check` | NG | 1（即個別報告） | Figma のパス表記と衝突する |
| `#` | `label#123` | NG | 1（即個別報告） | Component Property の内部IDと紛らわしい |
| `.` `:` `(` `)` | `card(ver3.0)` | NG | 1（即個別報告） | 値のパース時に問題を起こす |
| `_` | `spacer_left` | NG | 2（まとめて報告可） | 検索・操作は可能だが表記として禁止 |
| `-` | `xx-small` | NG | 2（まとめて報告可） | 同上 |

- **報告優先度2はまとめて報告してよいが、修正自体は省略できない。**（例：`spacer_left → spacerLeft` のように、同じ変換をまとめて件数とともに提示）
- 修正の着手順は報告優先度1→2の順

## 3. 追加ルール（R-04〜R-10）

基本形式にマッチしていても、次を守る（❌の例に該当する場合は違反）。

| ルール | 内容 |
|---|---|
| R-04 | 意味のある名前にする（❌ 末尾の機械的な連番：`item01` `card02`） |
| R-05 | 用途を表す役割名にする（❌ Figmaのデフォルト名・素材名） |
| R-06 | 実際の用途に基づく名前にする（❌ ダミーテキスト由来の名前） |
| R-07 | 具体的な役割語を使う（❌ 禁止語：`group` `section` `wrapper` `box` `block` `row` `col`。`tableRow` を除く） |
| R-08 | 正しい英語の綴りにする（❌ 綴り誤り） |
| **R-09** | **数字を含めない**（❌ 種類を表す数字：`stamp1` `stamp2`。R-09の例外の表（px値・倍率）に当てはまる形のみ例外） |
| **R-10** | **Imageはフレームの中に置く**（❌ ページ直下・Group・Section直下の単独Image。名前ではなく配置のルール） |

### R-04（連番）

- 違反: (a) ゼロ埋め数字で終わる（`item01` `card02`）、(b) 兄弟レイヤーに「同じ語幹＋別の数字」が並んでいる（`item1` `item2` `item3`）
- 許容: R-09の例外の表に当てはまる数字のみ
- 判定に迷う場合は「要確認」として提示し、ユーザーの判断を仰ぐ
- 修正案の方針: 連番を除去し、可能な限り役割語で区別する（`itemTitle` `itemDate` 等）。役割で区別できない純粋な繰り返し要素は**同名を許容**する（`item` が複数並んでよい）
- **同名を許容するのは、同じ役割の要素が並ぶ場合（リストの行など）に限る。** このときAIは名前ではなく、親の中の順番（何番目か）で特定する。役割が違う要素に同じ名前を付けない（❌ タイトルと日付が両方 `text` → ✅ `title` `date`）

### R-05（デフォルト名・素材名）

**Figmaのデフォルト名**: 次の正規表現にマッチする場合に違反。

```
^(Frame|Group|Section|Slice|Component|Instance|Text)( \d+)?$
```

- **図形系・Imageの既定名は、英語版・日本語版とも違反としない**（下記「図形系の許容」を参照）
- **`Text`（TEXTノードの既定名）はR-05として報告する。** R-01（ケース違反）にも当たるが、役割が分からないことが本質のため
- **日本語版Figmaの既定名も、デフォルト名として違反とする。** 次の正規表現にマッチする場合に違反。実例：`グループ 12` `フレーム 3` `テキスト 5`。R-02（日本語）ではなく、役割が分からないことが本質のためR-05として報告する

```
^(グループ|フレーム|セクション|テキスト)( \d+)?$
```

#### 図形系の許容

次の名前に**完全一致**するレイヤーは、R-01〜R-09を適用しない（違反にしない）。スペース＋数字の付いたもの（`Rectangle 12`）も許容する。Figmaが自動で採番する名前のため。

```
^(Rectangle|Line|Arrow|Ellipse|Polygon|Star|Vector|Path|Union|Subtract|Intersect|Exclude|長方形|楕円形|多角形|星|スター|直線|線|矢印|パス|ベクター|前面オブジェクトで型抜き|背面オブジェクトで型抜き)( \d+)?$
```

- **リネームした場合は通常ルールで判定する。** 役割名に変えたものはR-01〜R-09の対象。`Rectangle background` のように既定名と役割語が混在したものは違反
- **推奨（違反ではない）**: 背景・区切り線など役割のある図形は、AIが名前で操作できるよう役割名（`background` `divider` 等）を付けることを推奨する
- **`Image` / `Image N` / `画像`**: **フレーム内にある場合のみ**同様に許容する。フレーム外の単独ImageはR-10で違反（名前に関わらず判定する）
- Union / Subtract / Intersect / Exclude の**子レイヤー**は、通常ルールで判定する

**素材名**: アイコンフォント等の素材名をそのまま使っている場合も違反とする。

- 判定: `_FILL` `_wght` `_GRAD` `_opsz` のいずれかを含む。これ以外の素材パラメータを見つけた場合は「要確認」として報告し、この一覧への追加はユーザーが判断する
- 実例: `arrow_drop_down_FILL1_wght400_GRAD0_opsz24`、`circle_FILL0_wght400_GRAD0_opsz24 2`
- **修正案は機械的な変換をしない。** `arrowDropDownFill1Wght400Grad0Opsz24` のような名前にせず、**用途を表す役割名**にする（例: `dropdownIcon`）

R-05 に該当する場合、他のルールは併記しない（デフォルト名・素材名であることが本質的な問題のため）。

### R-06（ダミーテキスト）

次のいずれかに当てはまる名前を違反とする。単語は camelCase の区切りで数える。

| # | 条件 | 例 |
|---|---|---|
| (a) | 同じ単語が続く | `textText` `itemItemItem` |
| (b) | 同じ文字が3回以上続く | `aaaa` `xxx` |
| (c) | プレースホルダー語を単語として含む：`lorem` `ipsum` `dummy` `hoge` `fuga` `piyo` | `loremIpsum` `dummyTitle` |
| (d) | キーボードで隣り合うキーが4文字以上続く | `asdf` `qwer` |

- (a)〜(d)に当たらないが意味のない文字列に見えるものは「要確認」として提示し、ユーザーの判断を仰ぐ
- 日本語のダミーテキストは R-02 で検出されるため、R-06 は主に英語・繰り返しパターンを対象とする

### R-07（禁止語）

- 禁止語: `group` `section` `wrapper` `box` `block` `row` `col`
- レイヤー名を camelCase の単語単位に分割し、禁止語が単語として含まれていたら違反（`contentsGroup` `sectionHeader` `buttonRow` も違反）
- **例外：名前が `tableRow` と完全一致する場合は、`row` を含んでも違反にしない**（表のデータ行。第5節）
- 名前に `buttonSet` または `btns`（ボタンの箱）を含むものも違反。`container` にする（第5節）
- **1語の英単語の一部に含まれるだけなら違反にしない**（✅ `checkbox` `textbox` `toolbox` `arrow`）。ただし、その英単語を区切って書いたものは違反とし、1語に直す（❌ `checkBox` → ✅ `checkbox`）
- 修正案では第5節「グループを表す語」への置き換えを提案する

### R-08（綴り誤り）

英単語として存在しない綴りを違反とする。**形式が正しくても、綴りが違えばAIは名前を再現できない。**

| 実例 | 正 |
|---|---|
| `card_thumnails` | thumbnails |
| `defualt` | default |
| `inputing` | inputting |
| `disable`（状態を表す場合） | disabled |

- **米国英語の綴りを正とする**（✅ `color` `center` ❌ `colour` `centre`）。実装コード（CSS）の綴りと揃えるため
- **対象外の語は次の一覧に限る**：`<serviceName>` `<承認した外来語>`（組織固有語・製品名・承認済みの外来語。導入先で列挙する）。一覧にない語で英単語かどうか判断できない場合は「要確認」として提示し、一覧への追加はユーザーが判断する
- 綴り誤りは R-01〜R-03 と併記してよい（形式と綴りは別の問題のため）
- 修正案は正しい綴りに直したものを1つ出す

### R-09（数字の制限）

**レイヤー名に数字を含めない。** 種類・バリエーションを表す数字（`stamp1` `stamp2` `icon3`）は、AIが「連番として違反」か「意味のある区別」かを一意に判断できないため、原則として禁止する。

| 実例 | 修正案の方針 |
|---|---|
| `stamp1` `stamp2` | 役割語へ置き換える（例: `coinStamp` `starStamp`） |
| `icon3` | 具体的な用途名へ置き換える（例: `searchIcon`） |

**例外：数字は、次の表の形に当てはまる場合だけ使える。** 表にない数字はすべて違反とする。

| 用途 | 形 | 判定 | 例 |
|---|---|---|---|
| px値 | 数字の直後に `px` を付ける | 数字の直後が `px` | ✅ `icon24px` ❌ `icon24`（何の数字か分からない） |
| 倍率 | 数字の直後に `x` を付ける | 数字の直後が `x` | `icon2x` |

- 表にない用途で数字が必要になった場合は、違反として報告したうえで「要確認」とし、表への追加はユーザーが判断する
- `ver`軸の値はレイヤー名ではないため、この表の対象外（[variant-naming-rules.md](variant-naming-rules.md) V-04-3）。バージョンはこの軸の値でのみ管理し、レイヤー名に含めない（CA-01）

機械的な連番（`item01` `card02`）はR-04で、R-09はそれ以外の「種類を表す数字」全般を扱う。

### R-10（単独Image）

**Imageはフレームの中に置く。** 名前ではなく、親ノードの種別で判定する。

- **対象**: 画像塗り（IMAGE fill）を持つノード（通常は `Rectangle` 型）。名前は問わない（リネーム済みでも判定する）
- **許容**: 親が FRAME / COMPONENT / COMPONENT_SET / INSTANCE
- **違反**: 親がページ直下、GROUP、SECTION、BOOLEAN_OPERATION など上記以外（Groupは禁止語（R-07）のため、フレームに置き換える）
- **修正案の方針**: 画像をフレーム（Auto Layout推奨）に入れる。フレームの名前は通常ルール（R-01〜R-09）で付ける
- フレーム内のImageの名前は、既定名のままでも許容する（R-05「図形系の許容」）

## 4. 特殊なケースの修正方針

### 機械的変換の規則（表記ゆれを防ぐ）

記号や大文字を含む名前を lowerCamelCase へ直すとき、**判断が入ると修正のたびに表記が揺れる。** 次の規則で機械的に変換する。

**元の区切り（アンダースコア `_`、ハイフン `-`、スペース）でのみ単語を分ける。区切りのない箇所を勝手に分けない。**

| 変換前 | 変換後 | 補足 |
|---|---|---|
| `large_sidepanel` | `largeSidepanel` | `sidepanel` を `sidePanel` に**分けない** |
| `simple_large` | `simpleLarge` | |
| `error_description_only` | `errorDescriptionOnly` | |
| `show content_title` | `showContentTitle` | スペースも区切りとして扱う |
| `ruby_area` | `rubyArea` | |
| `Show ruby` | `showRuby` | 先頭を小文字化 |
| `Label` | `label` | 先頭を小文字化するだけ |

- **区切りを除去し、区切りの直後の文字を大文字にする。先頭は小文字にする**
- **全大文字の単語（頭字語）は、全小文字にしてからつなぐ**（`PDF_icon` → `pdfIcon`。❌ `pDFIcon`。R-01の細則と同じ）
- **元の綴りを変えない。** 単語の切り方を推測しない
- 綴り誤り（R-08）は別途修正する。変換と綴り修正を同時に行ってよい（`dargbtn_spacer` → `dragButtonSpacer`）
- 素材名・CSSユーティリティ風名・デフォルト名は**この規則を適用しない**。役割名に置き換える（下記参照）

この規則は **Variant値・Property名・Component Set名にも適用する**（`variant-naming-rules.md` から参照）。

### そのほかの修正方針

### CSS ユーティリティ風の名前

ユーティリティクラス列がそのまま名前になっているもの。

| 実例 | 修正案 |
|---|---|
| `titleArea row g-16 p-16` | `titleArea` |
| `body col g-16 px-8 pt-8 pb-16` | `calendarBody` など、役割を表す名前 |

**機械的にキャメルケース化しない。** 役割を表す部分だけを残すか、役割名を新たに与える。

### 数字の扱い

**R-09により、数字は原則禁止。** 例外はR-09の例外の表に当てはまる形だけ。

| 種類 | 扱い | 例 |
|---|---|---|
| px値を表す数値 | **許容。数字の直後に `px` を付ける**（R-09） | ✅ `icon24px` ❌ `icon24` |
| 倍率 | **許容**（R-09） | `icon2x` |
| 種類・バリエーションを表す数字 | **違反（R-09）** | ❌ `stamp1` `stamp2` `icon3` |
| 機械的な連番 | 違反（R-04） | `item01` `card02` |
| **レイヤー名・フレーム名へのバージョン番号** | **違反** | ❌ `card_ver3.0`（名前に埋め込む） |
| `ver`軸の値（Variant Property。レイヤー名ではない） | **許容** | `2` `2.1`（旧版は`🚫2`） |

**バージョン番号をレイヤー名・フレーム名に含めると、どれが正本か判別できなくなる。** バージョン管理は[variant-naming-rules.md](variant-naming-rules.md) V-04-3の`ver`軸の値でのみ行い、名前には入れない（[component-authoring-rules.md](component-authoring-rules.md) CA-01）。

## 5. 推奨語彙

修正案を提案する際は、以下の語彙を**優先して**使用する。表にない語も、**用語を見ればUI要素が誰でも判別できる明確な英単語**であれば使用してよい。

**略語は使わない。すべてフルスペルにする。** 語の一部を省いた綴りは、AIが元の語を一意に復元できず、名前が揺れるため（❌ `txt` `img` `btn` `bg` `nav` → ✅ `text` `image` `button` `background` `navigation`）。

- 頭字語（`pdf` `qr` `url` `ui` など、語の頭文字や固有の略称で一般に通じるもの）は略語ではない。R-01の細則に従い全小文字でつなぐ
- 略語かどうか判断に迷う語は「要確認」とする。承認した語を例外として扱う場合は、ユーザーが判断する

### 役割を表す語

| 語 | 意味 |
|---|---|
| `label` | 項目名・見出しラベル |
| `title` | タイトル |
| `text` | 単独のテキスト要素 |
| `caption` | 補足テキスト・キャプション |
| `placeholder` | 未入力時の案内テキスト |
| `input` | 入力欄 |
| `error` | エラー表示 |
| `icon` / `～Icon` | アイコン（例: `appIcon` `dropdownIcon`）|
| `image` | 画像 |
| `thumbnail` | サムネイル画像 |
| `～Button` | ボタン（例: `closeButton`）|
| `tag` | タグ |
| `badge` | バッジ |
| `divider` | 区切り線 |
| `scrollBar` | スクロールバー |
| `～Navigation` | ナビゲーション |
| `list` | 一覧・リスト |
| `item` | リスト等の個別項目。表では、行（`tableRow`）とヘッダー行（`tableHeader`）の中のセルのフレームを `tableItem` にする。列のまとまりを表す専用の名前は定義しない（`tableCol` `tableCell` は作らない） |
| `～Card` | カード型UI |
| `tab` | タブUI |
| `modal` | モーダルウィンドウ |
| `table` | 表全体 |
| `tableHeader` | テーブルのヘッダー行。中のセルのフレームは `tableItem` |
| `tableRow` | テーブルのデータ行。中のセルのフレームは `tableItem` |
| `ruby` / `rubyArea` | ふりがな（日本語対応）。`ルビ`・`フリガナ`は日本語にせず`ruby`に統一する |
| `spacer` | 余白調整用の要素（例: `leftSpacer` `rightSpacer`。語順はR-01の語順細則に従う）|

### グループを表す語

| 語 | 使い方 |
|---|---|
| `container`（単独） | 役割を付けない箱。AIは中身を見て判断する。同じ親の直下に1つだけ |
| `～Area` | 役割名を付けたい箱（例: `titleArea` `actionArea`）。名前の形で `container` と区別する。単独の `area` は不可 |
| `content` | 親の主たる中身。単数形のみ（❌ `contents`） |
| `control` | 操作・入力要素の集まり。単数形のみ（❌ `controls`） |
| `list` / `item` | 同じ役割の要素の繰り返し（上の表） |
| `tableRow` | 表のデータ行。中のセルのフレームは `tableItem`（`tableHeader` の中のセルも同じ） |

| ❌ 使わない名前 | ✅ 直し先 |
|---|---|

| `buttonSet` `btns` | `container` |
| `contents` `controls`（複数形） | `content` `control` |
| `group` `section` `wrapper` `box` `block` | 役割語（R-07） |

## 6. 対象トップフレームの命名（F-01）

**画面フレームを対象とする場合のみ適用する。** DS公開Componentを対象とする場合は評価しない。

### 推奨形式

```
画面ID-画面名-画面状態-画面サイズ
```

例: `S_02_01-申請フォーム-エラー-w1366`

- **セグメント間の区切りは `-`（ハイフン）にする。** 画面ID内部の区切り（`_`）と役割を分けるため（例：`S_02_01`は`_`のまま、セグメント同士は`-`）
- **`-` はセグメントの区切りにだけ使う。** 画面ID・画面名・画面状態の中では使わない。AIが `-` で分割して各セグメントを一意に読み取れるようにするため
- `/`は使わない。Figmaの書き出し機能でパス区切りとして解釈され書き出しが壊れる、また`/`は[variant-naming-rules.md](variant-naming-rules.md) V-06でComponent Set階層として既に別の意味を持っているため

### 各セグメントの扱い

| セグメント | 要否 | 扱い |
|---|---|---|
| **画面ID** | 空欄を許容する | 要件書確定前の段階では記入できないことが多いため。**空欄の場合、ID部分とその直後の区切り文字（`-`）ごと省略する**（❌ `-applicationForm-エラー` → ✅ `applicationForm-エラー`）。記入する場合の正しい画面IDは画面要件書またはユーザーに確認する（推定して提案しない） |
| **画面名** | 必須 | 省略不可。**日本語を許容する**（例：`申請フォーム`）。英語の場合も可（例：`applicationForm`）。`-` は使わない |
| **画面状態** | 必須 | **自由記述（日本語可）でよい。語彙の統一・リスト管理は必須としない。** 画面の状態が分かる記述であればよい（厳密な表記統一は不要）。よくある例：`初期状態` `全画面表示` `エラー` `エンプティ` `入力前` `入力中` `入力後`（維持管理するリストではなく、参考例として示すのみ） |
| **画面サイズ** | 任意 | 画面幅のバリエーションがない画面では、セグメント自体を省略してよい。表記は`w`＋画面幅の数字（px、単位は付けない）。**値は画面に合わせて自由**（例：`w1366` `w1024` `w375`）。判定は正規表現 `^w\d+$` |

### レビュー時の判定方針

- **画面ID**：空欄であっても違反としない（要修正にしない）。記入されている場合のみ、画面要件書の内容と一致するかを確認する
- **画面名・画面状態**：空欄・判別不能な場合のみ「要修正」とする。**画面状態は語彙の一致を見ない。** 何らかの状態を表す記述が含まれているかどうかだけを確認する
- **画面サイズ**：`w`+数字の形式（`^w\d+$`）に合っているかのみ確認する。セグメント自体が無いことは違反としない
- **区切り**：セグメントの中に `-` が含まれていたら要修正とする

F-01 は R-01〜R-10 の対象外とする（アンダースコア・ハイフン・大文字・日本語を含む形式のため）。

## 7. 報告の優先順位

複数の違反がある場合、次の順に報告する。

1. **R-05**（デフォルト名・素材名）— 役割が全く分からない
2. **R-03 報告優先度1**（スペース・`/`・`#`・括弧）— レイヤーを特定できない
3. **R-02**（日本語・全角。R-02の例外に該当する場合を除く）— コード生成時に名前が定まらない
4. **R-08**（綴り誤り）— 名前を再現できない
5. **R-01**（ケース違反・語順違反）— 規則性が学習できない
6. **R-07**（禁止語）— 意味が曖昧
7. **R-04**（連番）— 役割で区別できていない
8. **R-09**（数字。R-09の例外に該当する場合を除く）— 種類が数字でしか区別できていない
9. **R-03 報告優先度2**（`_` `-`）— 一貫していれば実害は限定的
10. **R-06**（ダミーテキスト）
11. **R-10**（単独Image）— 名前ではなく配置の違反のため、名前系の違反とは別枠で報告する

件数の多さで順序を決めない。**R-03報告優先度2の違反が数百件あっても、報告優先度1の違反1件を先に報告する。**
