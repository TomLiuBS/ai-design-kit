# デザインシステムマップ

各デザインシステムの**所在**を1か所にまとめた地図。Claude Code / Codex / Figma Agent が「どのファイルのどこを読めばよいか」を判断するために参照する。

**この文書は「所在」だけを持つ。** 部品名・Variant値・トークン名・スコアは書かない。DSレビューでそれらを直すと map が古くなるため。所在（ファイルキー・node-id）はリネームでは変わらない。

配置: `guidelines/design-system-map.md`

> **このファイルはテンプレートである。** 導入時に `<...>` の部分を実際の値に置き換える。行は必要に応じて増減する。

---

## 1. 参照の原則

1. **共通ガイドラインには必ず従う**
2. 対象サービスのDSを最優先で参照する
3. 対象サービスにない場合は共通UI／共通ルールを使う
4. それでもない場合は他サービスのDSを**参考**として参照する（採用は要判断）
5. どこにもない新規UIは、作成した上で「DSに不足」として報告する

**取得範囲を絞る。** 例：「`<サービス名>` の画面を作る」なら **共通（ガイドライン＋共通UI）＋`<サービス名>` 固有** だけを読む。他サービスのDSは必要時のみ。

## 2. 所在一覧

### Layer 1・2：共通

| 区分 | ファイルキー | node-id | 状態 |
|---|---|---|---|
| 共通ガイドライン（基本方針・スタイル・命名等） | `<共通DSのfileKey>` | `<nodeId>` | `<機械可読か・含まれる内容（トーン&マナー、カラー、タイポ、状態変化 等）>` |
| 共通コンポーネント（共通UIライブラリ） | `<共通DSのfileKey>` | `<nodeId>` | `<Component Set の本体か・含まれる部品（Button / Form / Label / Modal 等）>` |

**Layer 1 と Layer 2 は別ページにする。** ガイドラインは解説文、共通コンポーネントは Component Set の本体。DSレビューで扱う Component Set はすべて共通コンポーネントの node-id 配下に置く。

### Layer 3：サービス固有DS（任意）

| サービス | ファイルキー | node-id | 備考 |
|---|---|---|---|
| `<サービス名>` | `<fileKey>` | `<nodeId>` | `<共通と同一ファイルか別ファイルか。ローカル実装の場所（例：guidelines/<service>/）。ページ名。複数版の併存があれば現行版>` |
| `<サービス名>` | `<fileKey>` | `<nodeId>` | `<備考>` |

- node-id は、画面モックが同居するページ全体ではなく、**DS本体（Component Set が集まるセクション）**を指す。ページ全体を指すと、DSレビューの範囲に画面モックが混ざり、結果が歪む
- 複数のDSが同一ファイル内にある場合は、そのことを備考に書く。その場合は「ライブラリを開く」のではなく「ファイル＋node-id で対象へ移動する」

### URLの組み立て方

```
https://www.figma.com/design/<fileKey>/<任意>?node-id=<nodeId>
```

- MCP に渡す node-id は**ハイフン区切り**（`<数字>-<数字>`）
- Plugin API（use_figma）で使う場合は**コロン区切り**に変換（`<数字>:<数字>`）

## 3. ブランチについて

作業用のブランチが存在する場合、ファイルキーがブランチキーに変わる。

```
https://www.figma.com/design/<本体キー>/branch/<ブランチキー>/...
→ ブランチを対象にする場合はブランチキーをファイルキーとして使う
```

**この map に載せる所在は本番（本体ファイル）のみ。** ブランチは本番へ反映する前の検証用であり、作り直しが起きる一時的な所在のため、ブランチキーは map に記載しない。ブランチを対象にする作業では、作業のたびにブランチのURLまたはキーを指定する。
