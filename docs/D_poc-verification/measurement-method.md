# D. PoC 検証の計測方法

キットを入れる前（Before）と後（After）で、**同じ依頼をしたときの手戻り・時間・品質**を比べるための測り方です。PoC ごとに、この方法で [measurement-sheet.csv](measurement-sheet.csv) を埋め、[report-template.md](report-template.md) にまとめます。記入例は [sample-baseline.md](sample-baseline.md)。

---

## 1. 比べ方の条件をそろえる

| 条件 | 決まり |
|---|---|
| モデル | Before と After で同じモデルを使う（例：Sonnet 5.5）。途中で変えない |
| 会話 | 画面づくりは新しい会話で始める。共有・環境設定・運用の相談は別の会話で行う |
| 最初の依頼文 | Before と After で同じ依頼文（[process.md の入力テンプレート](../B_design-rules/process.md)）を使う。素材・ルールについての指摘は最初の依頼文に書かない |
| 初版の保存 | 最初の出力ができた時点で、必ずコミットして残す（初版の品質を採点するため） |
| 指摘の範囲 | 初版を見て、素材・画面の正解との違いだけを指摘する。途中で仕様を変えない（変えたら分類 C で記録） |

---

## 2. 用語

| 用語 | 定義 |
|---|---|
| 依頼 | 人が送った1回のメッセージ（ツールの結果や自動メッセージは除く） |
| 指示 | 1回の依頼に含まれる個別の要望。箇条書き1つを1件とする |
| 手戻り | AIの出力をやり直させた指示。分類 A・B・D |
| 実稼働時間 | 依頼から次の依頼までの、記録された操作の間隔の合計。**5分を超える空白は除く**（確認待ち・離席） |
| 按分 | 1回の依頼に複数の指示があるときは、その依頼の時間・トークンを指示の数で均等に割る |

---

## 3. 指示の分類

| コード | 分類 | 判断の目安 | 手戻り |
|---|---|---|---|
| A1 | ルール | DESIGN.md・ルール文書に書かれたことに反していた | ○ |
| A2 | 素材の部品の選択・見た目 | 素材にある部品・アイコンを使っていない、または見た目が違った | ○ |
| A3 | 素材の値（サイズ・余白） | 部品のサイズや余白が素材と違った | ○ |
| B | 画面の正解との不一致 | 画面の Figma（素材以外）と違った | ○ |
| C | 仕様の追加・変更・決定 | 動き・文言・構成を人が決めた・変えた | — |
| D | AIの解釈ミス・不具合 | 指示の読み違い、勝手な追加、ほかの箇所の巻き込み、表示の不具合 | ○ |
| E | 人の側の訂正・伝え方 | 人の指示ミスの訂正、伝え方の行き違い | — |
| F | 本番との差の調査 | 本番の画面とのサイズ差などの調査 | — |
| G | 周辺作業 | コミット、共有、環境設定、運用の相談、質問 | — |
| H | 最初の作成依頼 | 最初の依頼 | — |

- A（A1〜A3）が「**素材・ルール起因の手戻り**」。キットで減らしたい対象です。
- 境界にあるものは、シートの「備考」に理由を書きます。

---

## 4. 指標

### 4-1. 速度と手戻り

| 指標 | 定義 |
|---|---|
| 依頼の数／指示の数 | 2章の定義で数える |
| 修正回数 | 分類 A〜E の指示の件数 |
| 手戻りの件数 | 分類 A・B・D の指示の件数 |
| 素材・ルール起因の件数 | 分類 A の件数（同じ論点の再指摘を含む） |
| 実稼働時間 | 全体と、分類ごと（按分） |
| 初期画面までの時間 | 最初の依頼から、初版がコミットされるまでの実稼働時間 |
| トークン | 入力／出力／キャッシュ読込／キャッシュ書込（Claude Code の会話ログ `~/.claude/projects/` の `.jsonl` から集計） |

### 4-2. 品質

| 指標 | 定義 |
|---|---|
| Q1 初版の定点チェック合格数 | 初版が定点チェック表（5章）の項目を満たした数 |
| Q2 素材・ルール起因の指摘件数 | 完成までの分類 A の件数 |
| Q3 再指摘の件数 | 同じ論点を2回以上指摘した件数 |
| Q4 チェックリストの合否 | [review-checklist.md](../B_design-rules/checklists/review-checklist.md) の合格項目数（初版と完成版） |
| Q5 画面レビューの点数 | ツールの総合点・アクセシビリティの点・P0/P1 の件数（初版と完成版） |
| Q6 「素材に不足」の報告数 | AIが不足として報告した部品・挙動の数と内容 |

### 4-3. 素材そのもの（6指標）

`design-system-measure` スキルで、同じ範囲を Before／After で測ります。

| 指標 | 計算 |
|---|---|
| 説明文の記載率 | 説明文がある Component Set・単体部品 ÷ 対象 |
| Variant 違反候補率 | 命名ルールに反する候補を含む部品 ÷ 対象 |
| レイヤー名の違反候補率 | 書式違反のレイヤー ÷ 評価したレイヤー |
| 部品化率 | インスタンス ÷（インスタンス ＋ フレーム ＋ グループ） |
| Auto Layout 適用率 | Auto Layout のフレーム ÷ すべてのフレーム |
| Variables 適用率 | 変数が当たっている値 ÷（当たっている値 ＋ 当てるべきなのに当たっていない値）。余白・間隔・色・文字ごと |

比率は、領域ごとの率を平均せず、分子と分母をそれぞれ足してから割ります。

---

## 5. 定点チェック表の作り方

Before の作業で指摘された論点を、1行ずつ表にします。After では、初版がそれぞれを満たしているかを ○／× で確認します（Q1）。

| No | 論点 | 正しい参照先 | 分類 | 指摘回数 | 直す場所 |
|---|---|---|---|---|---|
| P-01 | 例：トーストの見た目 | 素材 `toast` | A2 | 2 | 素材（Figma・CSS） |
| P-02 | 例：確認ダイアログ | 素材 `dialog` type=confirm | A2 | 1 | 素材 |
| P-03 | 例：一覧の行の高さ | 画面の Figma | B | 1 | 画面の Figma |

- 「直す場所」が素材の論点は、キットの整備で改善を狙う項目です。
- 画面の Figma の論点は、キットでは変わらない想定の対照として測ります。

---

## 6. 記録と集計の手順

1. PoC の会話ログ（`.jsonl`）から、依頼ごとの時刻・トークン・ツールの実行回数を取り出す（AIに集計を頼んでよい）。
2. 依頼文を指示に分け、3章の分類を付けて [measurement-sheet.csv](measurement-sheet.csv) に1行ずつ書く。分類はAIが案を出し、人が確認する。
3. 初版と完成版を、review-checklist と画面レビューのツールで採点する。
4. 素材の6指標を測る。
5. [report-template.md](report-template.md) にまとめる。
