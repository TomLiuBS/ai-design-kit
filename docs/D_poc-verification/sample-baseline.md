# 記入例：Before（ベースライン）の計測

過去の案件で、AIで画面のプロトタイプを作ったときの実測です。サービス名・画面名・Figma の所在は伏せています。**キットを入れる前の典型的な姿**として、レポートの書き方と数字の読み方の参考にしてください。

## 1. 条件

| 項目 | 内容 |
|---|---|
| 対象 | 業務アプリの一覧画面のプロトタイプ（2版） |
| 会話 | 3回（初版の作成／初版の修正／第2版） |
| モデル | Sonnet 5.5（3回とも） |
| データ源 | Claude Code の会話ログ |
| 素材の状態 | 共通の素材はあったが、部品の説明文がなく、命名もそろっていなかった |

## 3. 読み取れること

- 手戻りは時間の約2割。そのうち半分強（18件／31件）が素材・ルール起因だった。
- 素材起因の手戻りは最初の2回の会話に集中し、3回目では4件に減った。途中で部品の索引（`component-map.md`）を作ったことが効いた可能性がある（未検証）。
- 周辺作業（G）が時間の46%を占めた。After では、画面づくりと周辺作業を別の会話にすると比べやすい。
- 素材にない部品（P-13 など）は、AIが毎回それらしく作ったため、同じ指摘が繰り返された。「推測で埋めない」ルールと仮の部品の記録で減らす対象。
