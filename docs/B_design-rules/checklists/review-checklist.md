# 画面の自己レビュー チェックリスト

AIが画面を作ったあと、提出前に使う固定のチェックリストです。主観の良し悪しではなく、この項目の合否だけで判定します。
（AI用の詳細版は `.claude/skills/prototype-draft/reference/review-checklist.md`）

## 1. 素材とトークン

- [ ] 使っている部品のクラスは、すべて `guidelines/kit/components.css`（またはサービス固有の CSS）に実在する
- [ ] 色・余白・角丸・文字サイズ・影は、すべてトークン（`var(--…)`）で書かれている。値の直書きがない
- [ ] 素材にない部品を、感覚で作り込んでいない。必要なものは「素材に不足」として報告するか、仮の部品として修正メモに記録した
- [ ] 部品のサイズ・状態は、Figma の該当画面で使われているものと一致している（名前から推測していない）

## 2. 参照の順番

- [ ] 見た目が素材（Figma ライブラリ）と一致している
- [ ] 実装コードを参照したのは、素材に定義のない見た目・挙動を補うときだけ
- [ ] 素材とコードの見た目が食い違う箇所で、素材を優先している

## 3. 原則（B-1）

- [ ] 主ボタンは1画面に1つまで
- [ ] 文字のコントラスト 4.5:1 以上（大きい文字は 3:1）、部品の境界・アイコンは 3:1 以上
- [ ] 押せる領域は 24px 以上（スマートフォンの画面は 44px 以上）
- [ ] 文字は 12px 以上
- [ ] 色だけで意味を伝えていない。アイコンだけのボタンに名前がある
- [ ] 取り消せない操作の前に確認がある。保存・送信のあとに結果が表示される
- [ ] 入力エラーは該当欄の近くに、直し方を含めて表示される

## 4. 状態

- [ ] [state-checklist.md](state-checklist.md) の該当する状態がすべてある
- [ ] 該当しない状態は、省略せずに「該当なし」と明記している

## 5. Figma との照合

- [ ] 主要な要素の位置・幅・高さを Figma と照合し、2px 以上の差は直した
- [ ] 囲みのある領域（メニュー・カード・ダイアログなど）ごとに、内側の余白と部品の間隔が Figma（なければトークン）と一致している
- [ ] 状態違いの Figma のフレーム（初期表示・選択時・開いた状態）も確認した

## 6. 出力

- [ ] 置き場所・フォルダ名が `.claude/CLAUDE.md` のルールに沿っている
- [ ] 既存のファイルを無断で上書きしていない
- [ ] 不採用案・一時ファイルが残っていない
- [ ] ファイルを直接開いても（`file://`）崩れない
- [ ] 決まったことを `NOTES.md` に残した（30行以内）

## 判定

- すべて合格 → 合格。人のレビューへ
- 1つ以上不合格 → 直して再判定（**差し戻しは2回まで**）
- 2回直しても残る項目 → 残件の一覧を添えて人に判断を渡す
