# E. 次フェーズの候補

PoC の結果を見て、**効果が確かめられたものだけ**を足します。候補と、始める条件の目安です。

| 候補 | 内容 | 始める条件（目安） | 使うもの |
|---|---|---|---|
| 部品の追加 | 「素材に不足」の報告が多い部品を素材に入れる | 2件以上の PoC で報告が出た | `component-authoring-advisor`、同期の3スキル |
| 画面テンプレートの追加 | 一覧・詳細・入力・ダッシュボード・設定以外の型 | 同じ構成の画面を3回以上作った | `layout-patterns.md` |
| ダークモード・多言語 | トークンにモードを足す、文字の長さの扱いを決める | 実際に必要な画面がある | Figma の Variables のモード |
| コード基盤との対応 | 利用中のフレームワーク・部品ライブラリと素材の部品を対応させる | PoC が本番の開発に進む | `component-map.md` に列を足す |
| プロトタイプ → Figma の定常化 | 作った画面を毎回 Figma に書き起こす | デザイナーが Figma で仕上げる流れができた | `prototype-to-figma` |
| ユーザビリティテスト | 実際の利用者（または社内の方）に試してもらう | 画面の方向性で迷いが残った | 画面レビューツールのテスト機能など |
| 素材の品質の定期確認 | 月1回の実測、四半期ごとのDSレビュー | 素材の部品が20種を超えた | `design-system-measure`、`design-system-audit-skill` |
| 複数サービスへの展開 | `guidelines/<service>/` で固有の上乗せを持つ | 2つ目のサービスで使う | `design-system-generate`（モード B） |

## 判断のしかた

4. A の方針（[policy-roadmap-template.md](../A_policy-roadmap/policy-roadmap-template.md)）の MVP と次フェーズの表を更新する。
